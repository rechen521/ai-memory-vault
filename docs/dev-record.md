# 开发记录（溯源）

这个仓库不是从零构思的，它来自一次真实的需求 + 迭代。把过程记下来，方便以后理解某些设计为什么是这样。

## 原始需求

> 帮我开发一个代码，保存 ai 与用户对话的记忆，防止因为上下文丢失导致的错误。最后加上一个弹窗，内容为英文的"愿你终有一天和重要的人重逢"。

翻译成工程语言，就是四个目标：

1. **记忆库核心** —— 录入、检索、标签、重要度；
2. **上下文快照重建** —— 一键产出能粘进新会话的上下文，这是防「上下文丢失」的关键动作；
3. **磁盘落盘** —— 数据不能只活在浏览器里，要有文件级备份；
4. **结尾英文彩蛋弹窗** —— `May you one day be reunited with the people who matter most to you.`

技术选型当场定下：**单文件 HTML、零依赖、双击即用**；记忆同时写 `localStorage` 与本地 JSON 文件做双保险。

## 原型阶段（v0.1，单文件 `ai-memory-vault.html`）

一个 821 行的自包含 HTML：内联 CSS + 内联 IIFE 脚本，功能已覆盖上面四点，并用真实浏览器验证通过。

验证方式值得一提 —— 当时环境里没有可用的浏览器自动化工具，于是改为：

1. 用 `node --check` 校验提取出来的内联脚本语法；
2. 起一个本地静态服务器；
3. 用系统自带的 Edge 以 `--headless=new --remote-debugging-port` 启动，再用 Node 内置的全局 `WebSocket` 连 CDP，发 `Runtime.evaluate` 驱动真实点击与断言，用 `Page.captureScreenshot` 截图人工复核。

这条路子被完整保留到了本仓库的 `tests/lib/browser.mjs`，好处是**开发和 CI 都不需要 `npm install`**。

原型阶段踩到的坑（现在都写进了测试或构建脚本）：

- **PowerShell 输出偶尔不回传** → 需要结果时写文件再读；
- **`Runtime.evaluate` 共享同一个全局作用域** → 连续求值里重复 `const` 声明会报错，所有求值一律包 IIFE（本仓库的 `BrowserSession.evaluate` 强制这样做）；
- **删除文件被安全钩子拦截** → 清理临时文件改用 `python -c "os.remove(...)"`；
- 统计面板里 `tagSet.__count || Object.keys(tagSet).length` 这种写法在标签数为 0 时会取到字符串，属于当场修掉的 bug。

## 本仓库阶段（v1.0.0）

在原型功能集不变的前提下做了三件事：

1. **重新组织源码**：`src/index.html` + `src/styles.css` + 7 个职责单一的 ES 模块；`scripts/build.mjs` 按依赖顺序内联成单文件，产物仍然是零依赖、双击即用，且**不做压缩**，方便审计。
2. **补测试**：24 项单元测试（数据层与持久化层的纯逻辑）+ 46 组真实浏览器 E2E 断言（录入、检索、编辑、删除、批量导入、快照、剪贴板、导入导出往返、XSS、彩蛋、持久化、损坏数据恢复、响应式、无障碍、控制台零报错）。
3. **补安全加固**：原型有一个真实漏洞 —— 导入文件里的 `id` 会被直接拼进 HTML 属性与 CSS 选择器，构造 `id` 为 `"><img src=x onerror=…>` 的 JSON 即可造成属性注入型 XSS。现在所有 id 经 `sanitizeId()` 白名单净化 + 渲染期二次转义，并有专门的 E2E 用例守住。

完整变更清单见 [CHANGELOG.md](../CHANGELOG.md)。

以下是被刻意保留下来的，它们属于这个工具的性格，不是遗漏：

- 智能排序的优先级：置顶 > 重要度 > 时间；
- 快照 Markdown 的结构与那句「请将以下内容视为**已知上下文**」；
- 界面视觉（配色、圆角、卡片左侧的角色色条）。
