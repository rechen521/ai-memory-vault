# 数据格式

AI 记忆库的所有数据都是**纯 JSON 文本**，你随时可以打开、编辑、用脚本处理，或者迁移到别的工具里。

## 导出文件结构

```json
{
  "app": "ai-memory-vault",
  "version": 1,
  "exportedAt": "2026-10-16T14:22:34.000Z",
  "memories": [
    {
      "id": "m1a2b3c4d5",
      "role": "user",
      "content": "我 2026 年参加高考，物理方向，位次 12000 左右",
      "tags": ["个人信息", "高考"],
      "weight": 3,
      "pinned": true,
      "createdAt": 1792160555112,
      "updatedAt": 1792160555112
    }
  ]
}
```

## 字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `app` | string | 固定为 `ai-memory-vault`，用于识别文件来源 |
| `version` | number | 数据格式版本，当前为 `1` |
| `exportedAt` | string | 导出时间（ISO 8601，UTC） |
| `memories` | array | 记忆数组 |
| `memories[].id` | string | 记忆唯一标识，**只允许 `A-Za-z0-9_-`，最长 40 字符**；导入时其他字符会被剥离 |
| `memories[].role` | `"user"` \| `"ai"` | 说话方；其它值一律按 `user` 处理 |
| `memories[].content` | string | 记忆正文，最多 20000 字符，导入时自动 trim |
| `memories[].tags` | string[] | 标签，最多 12 个，每个最长 24 字符，大小写不敏感去重 |
| `memories[].weight` | 1 \| 2 \| 3 | 重要度星级，超出范围会被夹紧 |
| `memories[].pinned` | boolean | 是否置顶（智能排序中永远排最前） |
| `memories[].createdAt` | number | 创建时间（毫秒时间戳） |
| `memories[].updatedAt` | number | 最后修改时间（毫秒时间戳） |

机器可读的 JSON Schema 见 [`schema/memory-vault.schema.json`](../schema/memory-vault.schema.json)。

## 导入的容错规则

导入时不需要严格符合上面的结构，解析器会尽量理解：

1. 顶层是数组 → 直接当作记忆数组；
2. 顶层是 `{ "memories": [...] }` → 取 `memories`；
3. 顶层是单条记忆对象（含 `content`）→ 当作一条；
4. 其它情况 → 报「文件不是有效的记忆库 JSON」，不做任何改动。

合并策略（**不会覆盖已有数据**）：

- 按 `id` 去重：同 id 一律跳过（不更新）；
- 再按「角色 + 折叠空白后的内容」指纹去重：换过 id 的同一份备份不会重复入库；
- 空内容条目直接丢弃；
- 完成后提示「新增 N 条，跳过重复/空 M 条」。

## 本地存储位置

| 位置 | 内容 | 何时使用 |
|---|---|---|
| `localStorage` key `mvault.v1` | `{ memories: [...], updatedAt: 123 }` | 始终写入，刷新页面即恢复 |
| IndexedDB `mvault` → `kv` → `handle` | File System Access API 的文件句柄 | 点了「绑定本地文件」后，用于下次打开时恢复绑定 |
| 你绑定的本地文件 | 与导出文件完全相同的结构 | 每次修改后去抖 400ms 自动写入；页面切到后台时立即写入 |

> 解析失败时（例如手工改坏了 JSON），应用会提示「本地记忆读取失败」，然后以空库启动，**不会**清空原数据 —— 你可以先导出或直接用编辑器抢救 `localStorage` 里的内容。

## 上下文快照格式

快照不是 JSON，而是一段给 AI 看的 Markdown：

```markdown
# AI 上下文快照（由 AI 记忆库生成）

> 生成时间：2026-10-16 22:22
> 记忆条数：2（已筛选：标签 #高考）

请将以下内容视为**已知上下文**，不要重复询问，并保持前后一致；如与后续描述冲突，以用户最新表述为准。

---

### 1. 用户 · 2026-10-16 22:22  ★★★  [置顶]  #个人信息 #高考

我 2026 年参加高考，物理方向，位次 12000 左右

---

（以上为历史记忆，请在此基础上继续。）
```

要点：

- 标题层级用 `###`，方便 AI 按条目切分；
- 每条都带角色、时间、星级、标签、置顶标记；
- 当前有筛选（标签 / 关键词）时会写明范围，避免 AI 误以为这就是全部记忆；
- 默认只导出**当前列表可见**的记忆，想导出全部请先清空搜索与筛选。
